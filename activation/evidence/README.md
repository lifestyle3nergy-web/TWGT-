# Activation Evidence

Validation evidence for activation artifacts. Evidence should identify the source revision, validation result, and timestamp where practical.

## Bootstrap trust boundary

Bootstrap evidence is not generated by the repository. Authoritative nucleus commits, rollback pins, signing keys, signatures, and repository inventory are supplied by the external governance/issuance process.

The repository must never fabricate or silently replace those values.

## Verification

`activation/scripts/verify-bootstrap-evidence.sh` is fail-closed. It rejects missing, malformed, placeholder, or unverifiable trust material and verifies SHA-256 digests over the exact bytes of referenced repository artifacts.

The signature layer is intentionally pluggable. Until TWGT maintainers define the authoritative signature algorithm and canonical signed payload, the verifier rejects all signature algorithms rather than guessing one.

## Digest contract

Evidence digest keys are repository-relative file paths. The verifier hashes each referenced file as raw bytes with SHA-256 and compares the resulting lowercase hexadecimal digest with the evidence value.

The authoritative artifact set and signed-payload canonicalization must be defined by governance before cryptographic activation can pass.

## No activation bypass

A structurally valid template is not activation evidence. Placeholder values, generated test keys, dummy signatures, and inferred repository inventories must not be committed as production trust material.
